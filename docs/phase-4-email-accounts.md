# ขอบเขต 4 — ยืนยันอีเมลและกู้รหัสผ่าน

อัปเดต 25 กันยายน 2026: ข้อความด้านล่างบันทึก flow เดิม ปัจจุบันสมัคร Customer/Mechanic โดยไม่บังคับอีเมลและเข้าใช้ได้ทันที ไม่ส่งอีเมลยืนยันการสมัคร หน้ารีเซ็ตด้วย username และรหัสใหม่เปิดเฉพาะ Docker demo ที่ bind `127.0.0.1` และไม่รับบัญชี Admin หรือบัญชีที่ถูกปิด หลังรีเซ็ตระบบเพิกถอน OIDC token เดิม การเปลี่ยนอีเมลจากหน้าโปรไฟล์ยังต้องยืนยันอีเมลใหม่ ส่วนการรีเซ็ตบัญชี Admin ให้ใช้ Django Admin หรือ `manage.py changepassword` วิธีรีเซ็ตด้วย username ไม่มีหลักฐานว่าเป็นเจ้าของบัญชี จึงห้ามเปิดจากภายนอก

บัญชีที่สมัครใหม่ (ทั้งสมาชิกทั่วไปและผู้ให้บริการ) ถูกสร้างเป็น inactive ก่อน เมื่อส่งฟอร์มสำเร็จระบบส่งลิงก์ยืนยันอีเมล ผู้ใช้เปิดลิงก์และกดปุ่มยืนยันจึงเข้าสู่ระบบผ่าน OIDC เดิมได้ ร้านของผู้ให้บริการจะยังไม่แสดงให้ลูกค้าเห็นหรือจองจนกว่าเจ้าของบัญชีจะยืนยันอีเมล ลิงก์มีอายุ 24 ชั่วโมง ใช้ได้ครั้งเดียว และไม่เปิดเผยอีเมลหรือ password hash ใน URL บัญชีเดิมที่ Admin ปิดใช้งานไม่สามารถใช้ลิงก์นี้เปิดบัญชีเอง

หน้าโปรไฟล์พักอีเมลใหม่ไว้ใน `pending_email` ขณะรอยืนยัน จึงไม่แทนอีเมลหลักใน OIDC หรือกู้รหัสผ่านก่อนกดลิงก์ ระบบบันทึก `email_verified_at` เมื่อยืนยันแล้ว บัญชีเดิมที่สร้างก่อนฟีเจอร์นี้ยังใช้งานได้ แต่ถือว่าสถานะการยืนยันอีเมลไม่ทราบจนกว่าจะยืนยันอีเมลใหม่

หน้า Login มี **ลืมรหัสผ่าน** และ **ส่งลิงก์ยืนยันอีเมลอีกครั้ง** การกู้รหัสผ่านใช้ views และ token ของ Django 5.2; เมื่อตั้งรหัสผ่านสำเร็จ ระบบเพิกถอน OIDC tokens ของบัญชีนั้นด้วย แบบฟอร์มขอลิงก์ตอบแบบเดียวกันทั้งอีเมลที่มีและไม่มีบัญชี และจำกัดการขอซ้ำต่ออีเมล 60 วินาทีผ่าน Django cache สำหรับ production หลาย worker ต้องกำหนด shared cache

หน้ากู้รหัสผ่านใช้รูปแบบการกรอกและหน้าตาใกล้ THE_ONE แต่แก้จุดเสี่ยงของระบบอ้างอิง: THE_X ไม่ยอมให้ผู้ที่ทราบเพียงอีเมลกำหนดรหัสใหม่ทันที ผู้ใช้ต้องเปิดลิงก์ใช้ครั้งเดียวจากอีเมลก่อน แล้วจึงกรอกรหัสใหม่และยืนยันรหัสในหน้าที่สอง ทุกช่องรหัสผ่านมีปุ่มแสดง/ซ่อนอยู่ในช่อง หลังเปลี่ยนสำเร็จระบบส่งอีเมลแจ้งเตือนและให้เข้าสู่ระบบผ่าน OIDC ใหม่

## การใช้งานบนเครื่องพัฒนา

ค่าเริ่มต้นของ `DJANGO_EMAIL_BACKEND` เมื่อ `DEBUG=true` คือ console backend ลิงก์จะพิมพ์ใน Terminal ที่รัน Django ไม่มีอีเมลส่งออกจริง เมื่อเปิดใช้จริงให้ตั้ง SMTP backend, host, port, TLS, บัญชีผู้ส่ง และ `DEFAULT_FROM_EMAIL` ผ่าน environment โดยไม่เก็บรหัสผ่านใน Git ค่า timeout ตั้งได้ด้วย `EMAIL_VERIFICATION_TIMEOUT` และ `PASSWORD_RESET_TIMEOUT`

หลัง pull โค้ดให้รัน migration เพิ่มฟิลด์โปรไฟล์และ unique index ของอีเมลที่รอยืนยัน:

```powershell
Set-Location 'D:\Project\Project_Flutter\mobiledev69\backend'
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py test garage --noinput
```

สมัครสมาชิก → ตรวจ Terminal Django → เปิดลิงก์ยืนยัน → กดยืนยัน → กลับแท็บ THE_X เดิมเพื่อเข้าสู่ระบบ การเปลี่ยนอีเมลจากหน้าโปรไฟล์ใช้ขั้นตอนยืนยันเดียวกัน ส่วนลืมรหัสผ่านเปิดจากหน้า Login และส่งลิงก์เฉพาะบัญชี active ที่มีรหัสผ่านใช้งานได้

ยังต้องกำหนด SMTP และ shared cache ของ production, ตรวจการส่งอีเมลจริง, ตั้ง HTTPS/domain และทดสอบ deploy ก่อนเปิดสมัครสมาชิกสาธารณะ ควรมีขั้นตอนจัดการบัญชีสมัครแล้วไม่ยืนยันเป็นเวลานานเพื่อไม่ให้อีเมลถูกจองค้าง
